# AI Video — локальный редактор видео

Приложение анализирует фотографии, видео и речь локальными моделями, сохраняет текстовый каталог с исходными таймкодами и собирает фильм по монтажному плану. Локальная страница позволяет редактировать сцены, титры и звук, сохранять варианты и управлять фоновой обработкой. Исходники используются только для чтения.

В репозитории хранятся код, интерфейс, тесты, зависимости и документация редактора. Материалы мероприятий, сценарии, монтажные планы, результаты анализа, модели и готовые фильмы остаются локальными и исключены через `.gitignore`.

## Подготовка

Требуются Windows и NVIDIA GPU с поддержкой CUDA и достаточной видеопамятью для локальных моделей. Основное окружение: Python 3.12, PyTorch 2.8.0 с CUDA 12.6, Transformers 4.57.6, Qwen3-VL-4B-Instruct и faster-whisper large-v3. Визуальный и речевой анализ выполняются последовательными отдельными процессами на GPU.

Откройте папку проекта в VS Code и выполните в PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/setup.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/download-models.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run.ps1 doctor
```

Setup устанавливает portable uv, Python, FFmpeg и зависимости из `uv.lock` внутри проекта. Системные PATH и реестр не меняются. Для первоначальной загрузки нужен интернет. Ревизии моделей сохраняются в `.tools/models.json`; обновление выполняется явно через `scripts/download-models.ps1 --refresh`. Анализ использует локальные веса и offline-режим библиотек. Скрытого перехода моделей на CPU нет.

## Анализ материалов

Разместите исходники в отдельной локальной папке, например `samples/my-event`. Результаты должны находиться вне папки исходников.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run.ps1 scan --source samples/my-event --output runs/event/media-index.json
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run.ps1 analyze --source samples/my-event --profile sample --output runs/event
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run.ps1 report --run runs/event
```

Профиль `sample` анализирует всю выбранную папку. Начальные параметры: интервалы по 10 секунд, 2 кадра/с, длинная сторона до 512 пикселей; последний неполный интервал сохраняется. Доступны `--window-s`, `--fps`, `--max-side`, `--decode`. Явный `--decode cpu` переключает только декодер FFmpeg; модели продолжают использовать GPU. Профиль `smoke` предназначен для подготовленной локальной тестовой подборки.

Основные результаты:

| Файл | Содержание |
| --- | --- |
| `media-index.json` | Относительные пути, метаданные и наличие звука. |
| `segments.jsonl` | Описания сцен и фотографий, сомнения и исходные ответы модели. |
| `transcripts.json` | Расшифровки и исходные таймкоды речи. |
| `analysis.md`, `preview.html` | Каталог и локальная проверка материала. |
| `metrics.json`, `run.json` | Измерения, параметры, состояние и ошибки обработки. |

Завершённые операции атомарно сохраняются в общем кеше `runs/cache`. Повторный запуск использует пригодные результаты; изменение исходника, параметров, инструкции или ревизии модели обновляет затронутые операции. После Ctrl+C повторите команду. Описания и расшифровки могут содержать ошибки и требуют содержательной проверки.

## Монтажный план

Подготовьте сценарий по текстовому каталогу и сохраните монтажный план, например в `edits/plan.json`. Пути `analysis` считаются относительно JSON; `source_id` берётся из каталога. Пример структуры без привязки к конкретному материалу:

```json
{
  "schema_version": 3,
  "title": "Мой фильм",
  "analysis": "../runs/event",
  "shots": [
    {"id": "scene_1", "source_id": "Camera/clip.mp4", "start_s": 0, "end_s": 5},
    {"id": "scene_2", "source_id": "Photos/photo.jpg", "duration_s": 3}
  ],
  "transitions": [
    {"from_shot_id": "scene_1", "to_shot_id": "scene_2", "type": "crossfade", "duration_s": 0.5}
  ],
  "titles": [
    {"id": "title_1", "text": "Мой фильм", "start_s": 0, "end_s": 3}
  ]
}
```

Замените исходник и диапазон в примере на существующие проанализированные материалы. Видео задаётся исходными `start_s`/`end_s`, фотография — `duration_s`. Титры имеют абсолютные таймкоды фильма и могут проходить через склейки. Пересекающиеся титры отклоняются. Для звука доступны `original`, `silence` и `source` с отдельными `source_id`, `start_s` и усилением `gain` от 0 до 4.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run.ps1 render --plan edits/plan.json --output runs/montage/film --check
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run.ps1 render --plan edits/plan.json --output runs/montage/film
```

По умолчанию экспортируется H.264, 1920×1080, 30 кадров/с, AAC 48 кГц. Кодирование выполняется NVENC, исходная скорость сохраняется, фото вписываются целиком. Проверяются наличие файлов, границы и покрытие сохранённым анализом. Кеш `runs/render-cache` позволяет повторно использовать неизменённые сцены. Общая громкость измеряется и выравнивается в два прохода; готовый MP4 публикуется после проверки таймлайна, звука и полного декодирования.

Результат содержит `film.mp4`, локальную страницу `watch.html`, монтажный лист `montage.md`, таймлайн, копию плана и диагностику. CLI сохраняет чтение планов версий 1 и 2. Редактор открывает их без перезаписи; первое сохранение создаёт резервную копию и записывает версию 3.

В `transitions` хранятся только эффекты между соседними сценами: `crossfade` — плавное смешивание, `fade_black` — через чёрный. Отсутствующая запись означает обычную склейку. Длительность эффекта содержит целое число кадров; фильм сокращается на сумму наложений (пример выше — 7,5 секунды). Входящий и исходящий эффекты вместе оставляют хотя бы один самостоятельный кадр сцены. Титры сохраняют абсолютное время и накладываются после смешивания изображения.

Codex выбирает переходы при составлении сценария по текстовому каталогу; инструкции сценаристу находятся в `AGENTS.md`. Редактор и сборщик используют сохранённые решения. При перестановке остаются только переходы между сохранившимися соседними парами; новые стыки получают обычную склейку.

## Редактор

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run.ps1 edit --plan edits/plan.json --port 8765
```

Откройте **http://127.0.0.1:8765** в Edge и оставьте терминал открытым.

- Слева — каталог с поиском, фильтрами и добавлением фрагментов.
- В центре — порядок сцен, перетаскивание, копирование, удаление и шкала монтажа.
- Между сценами — настройки стыка. Выберите эффект и длительность (по умолчанию 0,5 секунды с округлением до кадра), затем нажмите «Посмотреть стык». Справа появится короткий просмотр со звуком и титрами без сборки всего фильма. Подготовка выполняется из оригиналов до 720p с частотой кадров монтажа, сохраняется в кеше и управляется через общую очередь.
- Справа — просмотр сцены, границы, описание, звук и просмотр последнего собранного фильма.
- Границы видео, длительность фотографии и перехода меняются кнопками «−/+» или стрелками клавиатуры с шагом 0,5 секунды, округлённым до целого кадра монтажа. Значение в секундах можно ввести вручную; оно округляется до кадра. На границах допустимого диапазона соответствующая кнопка отключается.
- Под шапкой — общая сворачиваемая панель: «Титры фильма» выбранного варианта и «Обработка проекта» с общей очередью и счётчиком заданий. Красная урна удаляет титр; ↶ отменяет действие.

Правки сохраняются автоматически. «Сохранить как вариант» создаёт отдельный JSON, «История» восстанавливает сохранённую версию. Браузер и текстовые команды работают с одним планом; внешнее изменение файла проверяется по хешу перед записью. Ввод и выбранная сцена сохраняются при переключении общих вкладок. Титры за концом укороченного фильма отмечаются ошибкой, которую нужно исправить перед сборкой.

Прокси H.264/AAC до 720p готовятся лениво при просмотре, готовый фильм собирается из оригиналов. Фоновые задания выполняются последовательно; каждая сборка получает неизменяемую копию плана и отдельный результат. Закрытие вкладки не останавливает обработку. После Ctrl+C или перезапуска сервиса нажмите «Продолжить» для прерванных заданий. Состояние, история, прокси и задания находятся в `runs/editor`.

## Разработка

```powershell
.\.venv\Scripts\python.exe -m pytest --basetemp .tools/pytest-tmp
```

Тесты создают синтетические медиа и проверяют анализ, кириллицу в путях, таймкоды, кеш, восстановление, склейки, титры и сохранение вариантов. Браузерный сценарий использует Playwright и установленный Edge; дополнительные браузеры не скачиваются.

Локальный API читает `/api/project`, `/api/catalog`, `/api/plan`, `/api/history`, `/api/jobs`. Записывающие POST-запросы используют токен страницы `X-Editor-Token`. Сохранение и сборка принимают `variant` и текущую `revision`; конфликт возвращает HTTP 409. `POST /api/transition-preview` принимает `variant`, `revision`, `from_shot_id`, `to_shot_id` и возвращает задание `transition_preview`; готовое задание содержит `url`, в том числе при чтении `/api/jobs`. HTTP Range поддерживает перемотку зарегистрированных медиа.

Локальные материалы храните в игнорируемых `samples/`, `edits/`, `runs/` либо вне репозитория. Разовые сценарии приёмки и заметки о конкретных мероприятиях также остаются локальными. Требования к развитию приложения описаны в `FUNCTIONAL_DESCRIPTION.md`.
