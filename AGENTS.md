# Работа со сценариями и монтажными планами

Медиа и извлечённые кадры обрабатываются локально. Для сценария используйте готовый текстовый каталог и разрешённые расшифровки. Проекты UI хранят все данные мероприятия в выбранной рабочей папке вне приложения и исходников; не переносите их в Git. Для CLI явно указывайте папку исходников через `--source` и храните данные мероприятия вне приложения. Прежние планы поддерживаются через `edit --plan`; каталоги `edits/`, `samples/`, `runs/` остаются исключёнными из Git для совместимости.

Для проекта UI используйте скачанное задание `exports/ai-instructions.md`: оно содержит весь каталог и всю распознанную речь, разрешённую пользователем для этой выгрузки. Можно уточнять замысел в чате. Ответ оформляйте единым JSON `aivideo.scenario_bundle` версии 1 с точными `project_id`, `catalog_revision` и массивом `variants` из именованных планов версии 3. Каждый план содержит непустой итоговый `brief`. Поле `analysis` и локальные пути в ответ не включайте: их добавляет импортёр. Не изменяйте идентификаторы источников и не используйте интервалы вне проанализированных материалов.

При создании каждого нового сценария оценивайте переходы между всеми соседними сценами и выбирайте длительности по ритму материала:

- Обычная склейка подходит для динамичного действия и смены ракурса внутри одного события. Не добавляйте эффект без художественной причины.
- Плавное смешивание (`crossfade`) подходит для спокойных общих планов и фотографий.
- Переход через чёрный (`fade_black`) подходит для разделения эпизодов, времени или места.

Записывайте решения в монтажный план `schema_version: 3` по примеру в README. В массив `transitions` включайте только эффекты; отсутствие записи для пары означает обычную склейку. Продолжительность содержит целое число кадров монтажа. Наложения сокращают фильм и вместе должны оставлять минимум один самостоятельный кадр каждой сцены. Рассчитывайте итоговую длину до размещения абсолютных титров и проверяйте план через `render --check`.

Переход относится к паре идентификаторов соседних сцен. После изменения порядка сохраняйте только эффекты у оставшихся соседними пар; новые стыки получают обычную склейку. Существующие ручные решения сохраняйте при локальных правках, загрузке и пересборке, пока пользователь не попросит их изменить. Не дублируйте переход сценовыми `fade_in_s`/`fade_out_s`; прежние явно заданные появления и затемнения поддерживаются для совместимости.
